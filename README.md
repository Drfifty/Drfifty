# رِفد — نموذج إدارة العمل التنفيذي للمستشفى

واجهة عربية RTL تفاعلية لإدارة مكتب مدير المستشفى: مصفوفة آيزنهاور، سجل الطلبات، تواجد المدير والنواب والموظفين، تسليم وتغطية الغياب، طلب معلومة أو مستند، وخطة الغد والأيام الستة التالية بوحدات نصف ساعة تظهر داخل الموجز اليومي، إلى جانب التواصل والطابور والأجندة والقرارات.

> **هذه نسخة واجهة أولية وليست نظاماً إنتاجياً.** الحالات والرسائل والخطة محفوظة في `localStorage` على المتصفح الحالي فقط؛ لا يوجد خادم أو مزامنة بين الأجهزة أو تنبيه حقيقي. تبديل الأدوار للعرض فقط ولا يوفر مصادقة أو عزل بيانات. لا تستخدم بيانات مرضى أو معلومات سرية.

## تشغيل المعاينة

لا توجد حزم أو عملية بناء مطلوبة:

```bash
python3 -m http.server 4173 --bind 0.0.0.0
```

ثم افتح `http://localhost:4173`. يتطلب تثبيت الـ PWA وعمل Service Worker على أجهزة الشبكة اتصالاً آمناً (HTTPS بشهادة داخلية موثوقة، أو `localhost`)؛ خادم HTTP البسيط مناسب للمعاينة فقط، وليس للنشر في شبكة المستشفى.

## ما يمكن تجربته

- التبديل بين أدوار المدير والنواب والطبيب المصرح والسكرتير ورئيس القسم والموظف.
- تصفح مصفوفة آيزنهاور وسجل الطلبات، ونقل معاملة بين المربعات.
- مشاهدة حالة تواجد المدير والنواب في الشريط أعلى الصفحات؛ وتحديث مكان العمل العام ومدة الغياب دون GPS أو عنوان منزل.
- من شاشة تواجد الموظفين يمكن إرسال طلب معلومة أو مستند، والرد عليه من شاشة الموظف؛ المحاكاة محلية على المتصفح ولا ترسل إشعاراً أو مرفقاً فعلياً.
- في «الموجز اليومي» تظهر خطة الغد والأيام الستة التالية (٧ أيام من الغد) مع وقت احتياطي للطوارئ؛ يمكن فتح الخطة لإضافة مهام يدوية وتعديل اسمها وموعدها وأولويتها وتقديرها، والمهام العاجلة تعيد ترتيب الأقل أولوية.
- عند اختيار الموظف «غائب» أو «في قسم آخر»، يلزمه اختيار بديل من المسجلين في النموذج كمؤهلين ومتواجدين بالقسم وكتابة تسليم مختصر؛ وإذا لم يجد بديلاً، تُحال الحالة إلى المشرف وتظهر في قائمة التغطيات التي تحتاج توزيعاً.
- البديل المرشح يرى التسليم عند فتح حسابه في نموذج العرض فقط؛ لا يوجد إشعار أو قبول أو تعيين فعلي من خادم.
- حفظ اقتراحات تصنيف محلية من النقل اليدوي، ثم تطبيقها على طلب مشابه من القسم نفسه.
- إنشاء طلب، تعيين جهة متابعة، وتسجيل رد تجريبي أو استدعاء شخصي للمعاملة السرية.
- تحديد حالة عدم التفرغ، إضافة تعميم، إدارة طابور الزيارة، وعرض شاشة انتظار لا تعرض أسماء أو تفاصيل.
- إضافة مواعيد ووقت تركيز محمي إلى الأجندة، وتسجيل القرارات في الموجز.
- محاكاة موافقة تشغيلية مبدئية، ثم مطابقة السكرتير للنسخة الورقية، ثم تسجيل توقيع القلم بعد حدوثه فعلياً. هذا المسار ليس توقيعاً إلكترونياً معتمداً ولا يطلق إجراءً حقيقياً؛ والتوقيع الورقي اللاحق لا يمنح الخطوة الإلكترونية السابقة حجية قانونية تلقائياً.
- تفعيل نغمة محلية اختيارية عند إنشاء طلب عاجل.
- تثبيت غلاف التطبيق للعمل دون اتصال بعد زيارة أولى في متصفح يدعم ذلك؛ البيانات نفسها تبقى محلية على الجهاز ولا تتزامن بين الأجهزة.

## البنية

- `index.html` — نقطة دخول عربية RTL.
- `styles.css` — تخطيط متجاوب للهاتف وسطح المكتب.
- `app.js` — واجهة وسيناريوهات عرض تجريبية، دون خادم أو مكتبات خارجية.
- `sw.js` و`manifest.webmanifest` — تخزين غلاف التطبيق مؤقتاً للتشغيل دون اتصال.
- `rifd-mobile.html` — ملف مستقل مضمّن فيه التنسيق والبرمجية لفتحه محلياً على الهاتف عند تعذر معاينة Arena؛ لا يتطلب خادماً، لكن الحفظ يعتمد على دعم المتصفح لتخزين `file://`.
- `ARCHITECTURE.md` — حدود النموذج وتصميم مقترح للانتقال إلى نظام LAN آمن.

## قبل استخدام حقيقي

يلزم بناء API وخادم محلي، ومصادقة وصلاحيات خادمية، وPostgreSQL مع RLS، وسجل تدقيق غير قابل للتعديل، وتشفير ونسخ احتياطية، وقناة WebSocket موثقة، وتوقيع PDF معتمد. كما يلزم اختبار أمني وتشغيلي ومراجعة قانونية/سريرية. إذا احتاج موظف إلى الوصول من المنزل، يجب أن يمر عبر VPN مستشفى مُدار أو بوابة وصول آمنة معتمدة؛ لا يُكشف التطبيق أو قاعدة البيانات مباشرةً للإنترنت العام. راجع [وثيقة المعمارية](ARCHITECTURE.md)؛ الواجهة وحدها لا تحقق هذه الضوابط.
